# Онлайн-запись BookNow

Собственная форма работает на `https://za-granyu22.ru/#booking` через серверный API BookNow. Аккаунт `vr-arena-za-granyu` подключён 13 ноября 2026. Ключ находится только в закрытом файле настроек на сервере и передаётся контейнеру через окружение. На GitHub Pages и без серверных настроек остаётся пробная форма.

## Поведение

- Обычная форма получает локации, услуги, инструкторов и свободные сеансы через сервер. Создаёт запись через `POST /bookings` без бонуса.
- Календарь показывает ближайшие 14 дней для выбранной услуги; дни без свободного времени отключены. Другую дату в пределах 90 дней можно указать вручную. Время отображается в часовом поясе арены. Перед отправкой сервер заново проверяет доступность.
- Скрытая в BookNow цена не показывается в форме; длительность берётся из `duration.value` краткого каталога API.
- После колеса кнопка «Применить скидку к брони» открывает такую же форму в отдельном окне. Имя, телефон, процент и номер бонуса подставляются из результата.
- На основном сервере включено `PROMO_ENABLED=true`. После вращения кнопка «Применить скидку к брони» открывает форму поверх страницы. В ней видны бонус, обычная цена, экономия и предварительная цена со скидкой. Процент выбирается сервером: 5%, 7% или 10%, срок бонуса — 14 дней, один результат на телефон.
- Сервер проверяет бонус в SQLite, соответствие телефона и идентификатора браузера, срок действия и дату посещения. Процент из клиентского запроса игнорируется.
- В BookNow передаются пожелания по игре, число гостей и текст с подтверждённой скидкой. Это публичное примечание записи. Администратор применяет скидку к сумме вручную. Публичная схема создания записи не описывает применение процента или промокода, поэтому результат в форме обозначен как предварительный.
- Расчёт выполняется повторно на сервере из цены слота в копейках, количества и выданного процента. Процент, сумма и цена из клиентского запроса игнорируются. В примечании сохраняются исходная цена, сумма скидки и сумма после скидки; подтверждение формы показывает этот серверный расчёт. Скрытая цена не раскрывается в расчёте.
- Число гостей в компании передаётся в примечании. Количество бронируемых мест задаётся отдельно для коллективной услуги. Для обычной услуги оформляется один сеанс.
- Один бонус закрепляется за одной записью. Повторная отправка возвращает прежнее подтверждение. После неопределённого сетевого сбоя запрос и бонус остаются закреплёнными, новая запись автоматически не создаётся.
- Если BookNow однозначно отклонил запись с `422`, бонус можно использовать при исправленной повторной отправке.
- Результат вращения сохраняется на сервере сразу. В BookNow он попадает после отправки формы с датой и временем. Само вращение не создаёт бронирование.

## Сервер и настройки

`server/site-server.mjs` обслуживает статические страницы и `/api/booking/*`, `/api/promo/*`. Он использует существующую реализацию колеса в `promo-core.mjs`. Отдельный старый `promo-server.mjs` с универсальным webhook для этого сценария запускать не требуется.

Требуется Node.js 24+. Настройки заполняются на сервере в закрытом `.env` по `.env.example`.

```dotenv
BOOKNOW_ENABLED=true
BOOKNOW_API_KEY=secret_...
BOOKNOW_WORKSPACE=vr-arena-za-granyu
ALLOWED_ORIGINS=https://za-granyu22.ru
PROMO_SECRET=<случайный постоянный секрет длиной не менее 32 символов>
PROMO_DB_PATH=/app/.data/promo.sqlite
```

`PROMO_SECRET` и база должны сохраняться при обновлении контейнера. Реальные значения не публикуются в `dist/`, `docs/` и Git. `BOOKNOW_ENABLED=false` сохраняет пробный режим. Сервер формирует публичные `booknow-config.js` и `promo-config.js` сам. Ключ в них не передаётся. Колесо включается отдельно через `PROMO_ENABLED=true`; подключение бронирования не включает выдачу бонусов.

`Dockerfile` запускает сервер на Node.js 24. Каталог `/app/.data` подключается постоянным закрытым томом с правами пользователя `node` (UID 1000). Рабочий контейнер сохраняет имя `za-granyu22-site`, подключён к сети `nginx-proxy-manager_default` и слушает порт `80` через переменную окружения `PORT`. Nginx Proxy Manager продолжает направлять запросы на `za-granyu22-site:80`. Порт контейнера наружу не опубликован. `TRUST_PROXY=true` допустим только при доступе через доверенный прокси, который заменяет `X-Real-IP`.

Локальный запуск с настройками окружения

```sh
node --env-file=.env server/site-server.mjs
```

Без ключа можно проверить сохранение пробного режима

```sh
node server/site-server.mjs
```

## Проверка при подключении аккаунта

1. Проверить `/ping`, каталог услуг, цены, типы услуг и обязательные поля формы аккаунта. Групповые сессии типа `group` требуют отдельного сценария и пока направляются в виджет. Текущая форма поддерживает обычное бронирование одной услуги.
2. Проверить, какие услуги соответствуют форматам и длительностям на сайте. Услуга выбирается из реального каталога явно. Автоматического сопоставления похожих названий нет.
3. Сделать согласованную тестовую запись без бонуса и с бонусом. Проверить время Барнаула, цену, количество мест, статус, примечание и работу обязательных полей аккаунта.
4. Проверить отображение скидки в CRM и ручное изменение суммы администратором. Данные в предварительном расчёте формы не меняют сумму заказа в CRM.
5. Заполнить контакты арены и согласованные документы обработки данных до запуска для посетителей.

Если запрос получил состояние `uncertain`, найти его в CRM по номеру запроса из примечания. В SQLite `site_bookings` хранит идентификатор запроса и состояние. Бонус остаётся закреплённым до ручного разбора. Автоматического освобождения при отмене посещения пока нет.

## Проверка API от 13 ноября 2026

Актуальный OpenAPI подтверждает `POST /bookings`. Обязательные поля: `reserved_on` (UTC), `location_uuid`, `service_uuid`, `customer_phone`, `customer_first_name`. `staffer_uuid` требуется, если услуга не поддерживает автоматическое назначение. Дополнительные обязательные поля могут задаваться настройками аккаунта. При занятом слоте API возвращает `422`.

Свободное время получается через `GET /locations/{locationUuid}/time-slots`, услуги — через `GET /locations/{locationUuid}/services`. Все обращения к этим методам выполняются сервером с заголовками `Authorization: Bearer …` и `Workspace: …`. Секретный ключ нельзя добавлять в JavaScript сайта или публиковать в GitHub.

Рабочая проверка: создана тестовая запись «Тест сайта — не клиент» на услугу «Одиночная игра (будни)», 16 ноября 2026, 10:00–11:00 Asia/Barnaul, 900 ₽. Подтверждены `start_time=2026-11-16T03:00:00Z`, местное время 10:00, статус «Новый» и публичное примечание с номером запроса сайта. Затем запись отменена через API, подтверждён статус `CANCELED`.

Проверка колеса: браузер получил реальный бонус 5%. Кнопка открыла форму поверх сайта с подставленными контактами. Для слота 17 ноября 2026, 11:00–12:00 форма показала 900 ₽ → 855 ₽, экономию 45 ₽. Запись создана из этой формы; сервер вернул подтверждённый расчёт и привязку бонуса к записи. В BookNow процент и расчёт сохранены в публичном примечании; сумма самого заказа до ручного применения скидки остаётся 900 ₽. После проверки тестовая запись отменена, подтверждён статус `CANCELED`.

Настройки аккаунта требуют внимания: услуги с названием «будни» API сейчас разрешает выбирать и по выходным. Сайт следует расписанию BookNow, не подменяет его собственными правилами. В тарифных карточках сайта есть форматы, ещё не заведённые отдельными услугами в BookNow; форма предлагает только три реально доступные услуги аккаунта. Для услуги выходного дня в BookNow включено скрытие цены.
