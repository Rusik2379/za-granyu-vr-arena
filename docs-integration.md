# Колесо скидок и входящие заявки

Для нового сценария «колесо → форма с датой → запись со скидкой в примечании BookNow» подготовлен отдельный сервер сайта и собственная форма. Описание находится в [docs-booknow.md](docs-booknow.md). Подключение к аккаунту отложено по поручению владельца. Ниже описан ранее подготовленный самостоятельный обработчик входящих заявок без даты.

Посетитель вводит имя и мобильный телефон. Сервер выдаёт скидку, сохраняет заявку без даты посещения и отправляет её в настроенный входящий канал. Запись на сеанс при этом не создаётся.

## Что готово

- Форма и анимация колеса, отображение ранее выданного результата.
- Отдельный сервер `server/promo-server.mjs` на Node.js 24 и SQLite без внешних зависимостей.
- Один выигрыш на номер: `8 (999)…` и `+7 (999)…` считаются одним номером. Ограничение сохраняется после очистки браузера и перезапуска сервера. Уникальность задаёт база данных.
- Скидку выбирает сервер. Процент из браузера не принимается.
- Идентификатор браузера помогает вернуть прежний бонус при повторном запросе. Другой браузер с уже участвовавшим номером не получает чужой результат.
- IP используется для ограничения частоты запросов, а не как идентификатор человека. Один IP не запрещает участие нескольким гостям.
- Заявка сохраняется до отправки. При сбоях работает очередь с повторными попытками. Идентификатор заявки передаётся как `Idempotency-Key`; получатель должен учитывать его, чтобы не создавать дубли при потере ответа.
- В заявку включается `phoneVerified: false`: администратор проверяет владение номером при использовании скидки. Без SMS нельзя запретить участие с выдуманными или чужими номерами.
- Имена и телефоны реальных заявок не сохраняются в localStorage и не выводятся в открытой демо-админке. SQLite находится вне `dist/` и `docs/`, публичного API выгрузки нет.

## Ограничение BookNow

Проверено по [публичной OpenAPI-схеме](https://developers.booknow.ru/openapi.json) и [описанию бронирований](https://developers.booknow.ru/reference#tag/bookings) 2 ноября 2026 года.

`POST /bookings` создаёт клиента, лид, заказ **и бронирование услуги на конкретное время**. В опубликованной схеме отдельного метода создания лида только по имени, телефону и скидке нет. Этот метод нельзя использовать для колеса без даты: он создаст ненужную запись или вернёт ошибку.

Вебхуки, описанные в разделе BookNow «Вебхуки», отправляют события из BookNow наружу. Это не адрес приёма заявок с сайта.

Для немедленной передачи в BookNow нужен подтверждённый поддержкой способ создания входящего лида без записи: отдельный API, форма или иной поддерживаемый канал. Полученный контракт нужно подключить к функции `send` в `server/promo-server.mjs`. Текущий универсальный JSON-webhook — подготовленная точка подключения, **не готовый коннектор BookNow**. Реальные заявки в CRM не отправлялись.

## Что нужно для включения

1. Условия выбраны по поручению владельца: скидки 5%, 7% и 10%, срок 14 дней. Шесть равновероятных секторов `[5,7,10,5,7,5]`: вероятность 5% — 50%, 7% — ⅓, 10% — ⅙. Эти значения уже указаны в `.env.example`. В режиме предпросмотра выдаются только пробные результаты.
2. Выбрать сервер/хостинг с HTTPS и постоянным диском для SQLite. GitHub Pages обслуживает статические файлы и не выполняет этот обработчик.
3. Получить поддерживаемый входящий канал BookNow и адаптировать отправку к его документированному формату. Проверить доставку тестовой заявки в нужный аккаунт.
4. Заполнить серверные настройки по `.env.example`. Секреты хранить на сервере; не включать их в `dist`, `docs`, коммиты и клиентский JavaScript. `PROMO_SECRET` должен сохраняться между перезапусками, иначе изменятся ключи проверки номеров.
5. Указать адрес обработчика в `dist/promo-config.js`, например `apiBase:'https://api.example.ru/api/promo'`, и `mode:'live'`. До этого остаётся пробный режим. Неверный адрес живого API показывает ошибку; скрытого переключения на локальную имитацию нет.

```sh
node --env-file=.env server/promo-server.mjs
```

Сервер слушает `127.0.0.1:4180`; снаружи нужен HTTPS reverse proxy. `ALLOWED_ORIGIN` должен точно совпадать с origin сайта, например `https://rusik2379.github.io` без пути репозитория. Произвольные клиентские IP-заголовки игнорируются; при reverse proxy настройте ограничение частоты также на прокси. База `.data/promo.sqlite` должна сохраняться при обновлении приложения и входить в закрытую резервную копию. Нельзя размещать её в каталоге статического сайта.

Получатель webhook должен поддерживать идемпотентность по `Idempotency-Key`. После восьми неудачных попыток заявка остаётся в базе со статусом `failed` для разбора администратором; она не считается доставленной. Подтверждение `delivered` означает успешный ответ подключённого получателя, а не автоматически наличие в BookNow без проверенного коннектора.

## Формат подготовленной заявки

```json
{
  "id": "ZG-уникальный-идентификатор",
  "source": "za-granyu-discount-wheel",
  "name": "Имя гостя",
  "phone": "+79990000000",
  "discountPercent": 7,
  "expiresAt": "2026-11-16T12:00:00.000Z",
  "createdAt": "2026-11-02T12:00:00.000Z",
  "phoneVerified": false,
  "note": "Колесо скидок: 7%. Номер без SMS-подтверждения — проверить при использовании скидки"
}
```

Поля услуги, даты и времени бронирования намеренно отсутствуют: это заявка на скидку без записи на сеанс.
